v0.2.0은 admin 측 유저 삭제(백엔드 엔드포인트 + 프론트엔드 danger zone)를 도입하고 실사용 중 드러난 4건의 cross-component 런타임 버그를 정리한다 — LAN HTTP 환경에서 notifications/tabs/uploads가 크래시되던 문제, Files/Music/Video 탭이 닫히지 않던 문제, ForbiddenPanel 액션 버튼이 반응하지 않던 문제, About 다이얼로그의 stale 버전 리터럴. 릴리스 스크립트는 이제 세 버전 소스(VERSION, `package.json`, `frontend/package.json`)를 모두 lockstep으로 유지한다.

## 1. Features

### 1.1 Admin user delete

admin이 UserManager 디테일 패널에서 유저를 완전히 제거할 수 있다. 작업은 트랜잭션 안에서 유저 레코드와 관련 intent / identity / log 행을 한꺼번에 hard delete한다.

**Backend** (commit `e4d2b0b`):
- `DELETE /server/users/{userId}`가 admin-게이트된 토큰 그룹에 등록 (`backend/internal/server/router.go`).
- `admin.Handlers.DeleteUser`는 ADMIN role을 강제하고, admin lockout 방지를 위해 self-delete를 HTTP 400으로 거부하며, `db.ErrUserNotFound`를 HTTP 404로 매핑한다.
- `db.DeleteUser`는 cascade를 트랜잭션 안에서 실행 — 먼저 log 행을 명시적으로 제거하고(기존 `log.user_id NOT NULL` 스키마와 `ON DELETE SET NULL` 조합은 NOT NULL 제약을 위반하기 때문 — 잠재 schema bug를 애플리케이션 레이어에서 우회), 그 다음 유저를 삭제한다. `user_intents`와 `user_identities`는 의도대로 foreign key cascade로 따라간다.
- `db.ErrUserNotFound` sentinel을 도입하여 404 매핑을 깔끔하게 처리.
- 테스트 픽스처 `fullSchema`에 누락되어 있던 `user_identities`의 `FOREIGN KEY ... ON DELETE CASCADE`를 추가하여 테스트 커버리지가 production 동작과 일치하도록 정렬.

**Frontend** (commit `281a466`):
- `UserManager.svelte` 디테일 패널의 intents 카드 아래에 Trash2 아이콘과 "Delete user" 버튼을 가진 danger zone 추가.
- 확인 다이얼로그: `Delete user "<label>" (<id>)? This cannot be undone.`
- 수락 시 패널이 `DELETE /server/users/{userId}`를 호출하고 성공 시 유저 목록을 새로고침.
- admin이 자신의 행을 보고 있을 때는 버튼이 비활성화되고 그 이유를 인라인으로 표시(백엔드가 강제하는 가드와 같음 — UI 표면이 요청 자체가 시도되지 않도록 차단).
- 성공/실패는 기존 notifications 스토어로 노출.

## 2. Fixes

### 2.1 LAN HTTP 접근에서 notifications, tabs, uploads가 크래시되던 문제

(commit `025fe58`)

**증상:** HTTPS나 localhost가 아닌 LAN HTTP(`http://192.168.x.x`)로 접근한 설치본에서, 탭을 열거나 업로드를 큐잉하거나 어떤 notification이라도 트리거되면 즉시 uncaught error 발생. 로그인 실패 시 notifier를 호출하던 auth 흐름도 함께 중단되어 UI가 동결된 상태로 남음.

**원인:** 세 개의 스토어(`notifications.svelte.ts`, `tabs.svelte.ts`, `uploads.svelte.ts`)가 UI 키를 생성할 때 `crypto.randomUUID()`를 직접 호출하는 한 줄 짜리 코드를 들고 있었음. `crypto.randomUUID`는 secure context에서만 노출 — `localhost` 외부의 평문 HTTP에서는 `crypto`는 정의되어 있지만 `randomUUID` 멤버는 없어서 호출마다 throw.

**수정:** `frontend/src/lib/util/random-id.ts`에 공유 헬퍼를 추출 — `typeof crypto !== "undefined" && typeof crypto.randomUUID === "function"`로 게이트하고, 미충족 시 `Math.random` 기반 RFC 4122 v4 구현으로 fallback. 세 스토어는 이제 inline 호출 대신 이 헬퍼를 import. 이 식별자들은 UI 키(notification id, tab id, upload id)이지 보안 토큰이 아니므로 non-cryptographic fallback이 적절함.

### 2.2 Files / Music / Video 탭에 닫기 버튼이 없던 문제

(commit `3008b73`)

**증상:** 기본 Files 탭과 Music / Video 싱글톤이 표준 닫기(X) 컨트롤 없이 렌더링 — 사용자가 한 번 열린 후 닫을 수 없음.

**원인:** `TabStore.rootTab`이 `closable: false`로 생성되었고, 사이드바의 `activate` 경로가 Explorer / Music / Video 싱글톤에 동일 플래그를 명시적으로 강제했음. 원래 의도는 "사이드바가 유일한 복귀 통로" 였지만, 사이드바는 이미 존재하는 탭에 자동 포커스하고 없으면 새로 만들기 때문에 닫기 버튼은 비파괴적임 — 의도 자체가 무의미.

**수정:** `rootTab`이 이제 스토어 기본값 `closable: true`로 열림. 사이드바 activation 경로도 더 이상 override하지 않음. `TabStore.close`는 마지막 남은 탭을 닫는 edge case를 처리하도록 확장 — 새 Files `rootTab`을 삽입하고 선택해서 `TabContent`가 빈 페인을 렌더링하지 않도록 함.

### 2.3 ForbiddenPanel "Request admin permission" 버튼이 반응하지 않던 문제

(commit `6586f32`)

**증상:** `ForbiddenPanel`("Files are locked")에 도달한 신규 사용자가 "Request admin permission" 버튼을 아무리 눌러도 prompt 다이얼로그가 뜨지 않음.

**원인:** `Explorer.svelte`는 콘텐츠를 `<div data-marquee-canvas="true">`로 감싸고 `onpointerdown`에서 `setPointerCapture`를 호출함. `ForbiddenPanel`이 이 canvas 안에 렌더링되면서 `FileGrid`와 `FileList`가 이미 사용 중인 opt-out 마커가 없었음 — 따라서 `pointerup`이 canvas div로 리다이렉트되고 버튼에서 click 이벤트가 합성되지 않음. 결과적으로 `prompt()`가 호출되지 못함.

**수정:** `ForbiddenPanel` 루트 `<div>`에 `data-marquee-canvas="false"`를 추가하여 다른 곳에서 이미 사용 중인 opt-out 패턴과 정렬. 이제 버튼이 prompt 다이얼로그를 정상적으로 트리거.

### 2.4 About 다이얼로그가 stale "2.0.0"을 표시하던 문제

(commit `63f3a22`)

About 다이얼로그가 App version 행에 하드코드된 `"2.0.0"` 상수를 렌더링하고 있었음 — StatusBar는 빌드 타임 `__APP_VERSION__` 상수를 정상 표시하던 상태. 로컬 리터럴을 제거하고 다이얼로그도 `__APP_VERSION__`을 직접 읽도록 함. 두 UI 표면이 동일한 값을 표시(본 릴리스: `0.2.0`).

## 3. Infrastructure and Refactors

- **릴리스 파이프라인 lockstep을 루트 `package.json`까지 확장** (commit `0d519ff`). `scripts/release.sh`는 그동안 `VERSION`과 `frontend/package.json`만 sync — 루트 `package.json`은 Node-era 백엔드 제거 이후 `"1.0.0"`에 동결되어 있었음. 스크립트가 이제 두 `package.json` 파일을 모두 bump(추출된 `sync_pkg_version()` 헬퍼 경유)하고 릴리스 commit에서 함께 stage. v0.2.0부터 세 버전 소스가 항상 일치.
- **`.gitignore`** (commit `384ca76`). 로컬 데이터 디렉토리와 scratch 캡처 작업이 실수로 tracked되는 것을 막기 위해 `/data/`와 `/repo-visuals-work/` 추가.

## 4. Verification Summary

**Backend** — 신규 엔드포인트와 함께 통합 테스트 추가:
- `TestDeleteUser_CascadesIntentsAndIdentities`는 트랜잭션 경로를 실행하며 유저·intent·identity·log 행이 모두 제거됨을 assert.
- `TestDeleteUser_ReturnsErrUserNotFoundWhenMissing`는 sentinel이 핸들러 레이어에서 404로 깔끔히 매핑됨을 검증.

기존 정적 검사·빌드·나머지 통합 스위트는 변동 없음.

**Frontend** — 변경된 모든 표면을 end-to-end 브라우저 시나리오로 커버:
- Admin DELETE 흐름: admin이 자기 행을 보면 버튼이 비활성화(self-guard); 다른 유저를 삭제하면 목록에서 사라지고 디테일 패널 초기화.
- `random-id` fallback: secure-context 경로와 강제 fallback 경로 모두 UUID-v4 형태의 문자열을 생성; notifications 큐도 양쪽 모드 모두에서 정상 진행.
- 탭 closability: Files / Music / Video 탭이 닫기 컨트롤을 렌더링; 클릭 시 닫힘; 마지막 남은 탭을 닫으면 새 Files 탭이 삽입됨.
- `ForbiddenPanel`: "Request admin permission" 버튼이 prompt 다이얼로그를 안정적으로 트리거.

## 5. Known Limitations and Follow-ups

- 루트 `package.json`이 여전히 frontend 툴체인(Vite, SvelteKit, Tailwind, Svelte 5, TypeScript)을 pin — Docker 빌드의 첫 `npm ci`가 이걸 사용. 깔끔히 제거하려면 해당 devDependencies를 `frontend/package.json`으로 이전하여 빌드가 `frontend/` 안에서 완결되도록 해야 함. 그 아키텍처 정리가 들어오기 전까지는 릴리스 스크립트가 루트 `version` 필드를 lockstep으로 유지하여 더 이상 drift하지 않도록 함.
- `log.user_id NOT NULL` + `ON DELETE SET NULL` schema 불일치는 현재 `db.DeleteUser`에서 log 행을 명시적으로 삭제하는 방식으로 우회. NOT NULL 제약을 제거하거나 FK action을 변경하는 schema migration이 들어오면 데이터베이스가 cascade를 직접 강제할 수 있음; 후속 작업으로 트래킹.
- Admin user delete는 undo 없는 hard delete. soft-delete / 복원 흐름은 v0.2.0 범위 밖이며, 별도 feature 설계가 필요.
