## 1. User-Interface Refinements

### 1.1 favicon · static 에셋 · README 전반에 신규 브랜드 로고 적용

(commit `9351de7`)

단일 마스터 이미지(`Docs/images/logo-source.png`, 1254x1254 RGBA)가 모든 로고 변형의 정본. `scripts/regen-logos.py`가 Lanczos 리샘플링으로 전체 세트를 파생하여 인플레이스 기록:

| 출력 | 사이즈 | 소비자 |
|---|---|---|
| `frontend/static/favicon.ico` | multi-res (16/32/48/64) | 레거시 브라우저 탭 아이콘 |
| `frontend/static/favicon-16.png` | 16x16 | `app.html`의 `<link rel="icon">` |
| `frontend/static/favicon-32.png` | 32x32 | `app.html`의 `<link rel="icon">` |
| `frontend/static/favicon-48.png` | 48x48 | `app.html`의 `<link rel="icon">` |
| `frontend/static/favicon-64.png` | 64x64 | multi-res ICO 동반 |
| `frontend/static/apple-touch-icon.png` | 180x180 | iOS 홈스크린 마크 |
| `frontend/static/logo.png` | 256x256 | `Shell/Header.svelte` 브랜드 마크, login + localLogin 페이지 |
| `Docs/images/logo.png` | 256x256 | `README.md` + `README_EN.md` 임베드 |

`/logo.png`를 참조하는 Svelte 컴포넌트(`Shell/Header.svelte:51`, `routes/(auth)/login/+page.svelte:111`, `routes/(auth)/localLogin/+page.svelte:96`)와 `app.html:5-9`의 `<link rel="icon">` 선언은 이미 올바른 경로를 가리키고 있어 — 기저 PNG 바이트만 변경되고 코드 수정은 불필요.

`README.md`와 `README_EN.md`는 기존 hero GIF 위에 96px 로고를 작은 브랜드 마크로 임베드. 그 외 레이아웃 변경 없음.

`scripts/regen-logos.py`는 의도적으로 idempotent — 재실행 시 현재 `logo-source.png`로부터 모든 출력을 덮어씀. 향후 로고 리프레시는 마스터만 갱신하면 됨.

## 2. Verification Summary

표준 SvelteKit 파이프라인을 통한 프론트엔드 프로덕션 빌드(`vite build`)가 새 에셋과 함께 정상 완료 — 모든 static 참조(`/logo.png`, `favicon-*`, `apple-touch-icon.png`)가 resolve되고 출력이 `build/`에 경고 없이 기록됨.

재생성된 PNG의 시각 스팟체크 결과 hexagon outline과 cloud-stack 인테리어가 모든 사이즈에서 식별 가능함을 확인: 16x16 favicon에서도 hex 실루엣 인지 가능, 32x32에서 cloud 디테일 등장 시작, 180x180 apple-touch-icon은 마스터를 그대로 재현.

본 릴리스는 백엔드·프론트엔드 소스 코드·스키마·인프라 변경 없음 — 기존 통합 스위트와 CI 워크플로우는 영향받지 않음.

**본 릴리스 publish되는 GHCR 태그:**

| 태그 | 출처 |
|---|---|
| `:0.2.1` | `type=semver,pattern={{version}}` |
| `:0.2` | `type=semver,pattern={{major}}.{{minor}}` — `0.2.0` → `0.2.1`로 이동 |
| `:latest` | `flavor: latest=auto` — `0.2.0` → `0.2.1`로 이동 |

직전 patch 태그 `:0.2.0`은 원래 digest에 그대로 보존. 모든 태그는 `linux/amd64`와 `linux/arm64` 양쪽으로 publish.

## 3. Known Limitations and Follow-ups

- 옛 릴리스 노트(`v0.0.1-beta`, `v0.1.0`)는 게시된 GitHub Release 본문에서 여전히 상대 경로 cross-language 링크를 사용. `main`의 소스 파일은 해당 태그의 historical record 보존을 위해 그대로 둠 — 버그는 해당 옛 버전의 Release 페이지에서 클릭할 때만 영향. v0.2.0부터는 source와 Release 본문 모두 절대 URL 사용.
- `scripts/regen-logos.py`는 현재 대상 파일 목록이 하드코드. 새 consumer(PWA manifest icon, maskable Android icon 등) 추가 시 `TARGETS` 테이블 편집 필요 — 본 릴리스 블로커는 아니지만 향후 툴링 개선 포인트.
