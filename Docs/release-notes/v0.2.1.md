v0.2.1 is a brand-asset refresh. Every published logo surface — browser tab favicon, in-app header, login screens, README — now renders the new mark: an orange hexagon outline framing a stacked cloud / chevron silhouette. No application code or behavior changed.

---

## 1. User-Interface Refinements

### 1.1 New brand logo across favicon, static assets, and README

(commit `9351de7`)

A single master image (`Docs/images/logo-source.png`, 1254x1254 RGBA) is now the source of truth for every logo variant. `scripts/regen-logos.py` derives the full set with Lanczos resampling and writes them in place:

| Output | Size | Consumer |
|---|---|---|
| `frontend/static/favicon.ico` | multi-res (16/32/48/64) | Legacy browser tab icon |
| `frontend/static/favicon-16.png` | 16x16 | `<link rel="icon">` declared in `app.html` |
| `frontend/static/favicon-32.png` | 32x32 | `<link rel="icon">` declared in `app.html` |
| `frontend/static/favicon-48.png` | 48x48 | `<link rel="icon">` declared in `app.html` |
| `frontend/static/favicon-64.png` | 64x64 | Multi-res ICO companion |
| `frontend/static/apple-touch-icon.png` | 180x180 | iOS home-screen mark |
| `frontend/static/logo.png` | 256x256 | `Shell/Header.svelte` brand mark, login + localLogin pages |
| `Docs/images/logo.png` | 256x256 | `README.md` + `README_EN.md` embed |

Svelte components that reference `/logo.png` (`Shell/Header.svelte:51`, `routes/(auth)/login/+page.svelte:111`, `routes/(auth)/localLogin/+page.svelte:96`) and the `<link rel="icon">` declarations in `app.html:5-9` already pointed at the correct paths — only the underlying PNG bytes change, so no code edits were required.

Both `README.md` and `README_EN.md` now embed the 96px logo above the existing hero GIF as a small brand mark. No other layout changes.

`scripts/regen-logos.py` is intentionally idempotent: re-running it overwrites every output from the current `logo-source.png`, so future logo refreshes need touch only the master.

## 2. Verification Summary

The frontend production build (`vite build` via the standard SvelteKit pipeline) completes cleanly with the new assets bundled — every static reference (`/logo.png`, `favicon-*`, `apple-touch-icon.png`) resolves and the output writes to `build/` without warnings.

Visual spot-check of the regenerated PNGs confirmed the hexagon outline and cloud-stack interior remain readable at every size: the 16x16 favicon retains the recognizable hex silhouette, the 32x32 shows the cloud detail emerging, and the 180x180 apple-touch-icon reproduces the master at full fidelity.

No backend, no frontend source-code, no schema, and no infrastructure changes in this release — existing integration suites and CI workflows are unaffected.

## 3. Known Limitations and Follow-ups

- Older release notes (`v0.0.1-beta`, `v0.1.0`) still use relative cross-language links in their published GitHub Release bodies. The source files on `main` have been left untouched to preserve the historical record at those tags; the bug only affects clicks from the Release pages of those older versions. v0.2.0 onward uses absolute URLs both in source and in the Release body.
- `scripts/regen-logos.py` currently hardcodes the target file list. Adding a new consumer (e.g. a PWA manifest icon, a maskable Android icon) requires editing the `TARGETS` table; not a blocker for this release but worth noting as a future tooling improvement.
