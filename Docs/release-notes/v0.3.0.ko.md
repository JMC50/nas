v0.3.0은 파일 Explorer를 터치 우선 환경에 맞게 재정렬한다 — 데스크탑 동작은 변경 없음. 모바일에서 single-tap이 곧장 항목을 열고, long-press는 데스크탑이 우클릭으로 보던 것과 동일한 context menu를 표시하고, `md` 브레이크포인트 미만의 list view 행에는 long-press 제스처를 모르는 사용자도 즉시 접근할 수 있도록 kebab 어포던스가 노출되며, v0.2.x부터 모바일에서 이미 bottom sheet로 렌더링되던 Inspector는 핸들 드래그 dismiss를 지원하게 된다.

## 1. Features

### 1.1 모바일 인터랙션 모델 — single-tap open, long-press menu, kebab, swipe-to-dismiss

(commit `df3816a`)

**동작 변경 (모바일 viewport, `viewportWidth < 768`):**

| 제스처 | 기존 | 신규 |
|---|---|---|
| 항목 single-tap (선택 없음) | single selection (강조 ring만) | **열기** — 폴더는 진입, 파일은 viewer registry로 라우팅 |
| 항목 single-tap (선택 활성) | selection 토글 | 변경 없음 |
| 항목 long-press | 해당 항목 anchor로 selection mode 진입 | **context menu 열기** — 터치 지점에 데스크탑 우클릭과 동일한 메뉴 |
| list row kebab 탭 | (kebab 부재) | kebab 위치에 context menu |
| Inspector 핸들 드래그 | (핸들은 시각적 표시만) | 100px 초과 → 닫기, 미만 → snap back |

**선택 모드 진입** (새 경로): long-press 메뉴에 mobile 전용 "Select" 항목 추가 (`ContextMenu.svelte`의 `{#if ui.isMobile}`). 탭하면 long-press한 항목을 selection seed로 설정 — 기존 mobile selection bar가 나타나고, 이후 single-tap이 토글로 동작. `FileList` / `FileGrid`의 모바일 전용 `onLongSelect` 콜백은 제거 — long-press는 이제 prior state와 무관하게 일률적으로 "메뉴 표시"이며, 동일 제스처가 상태에 따라 다른 의미를 갖던 기존 500 ms 지연 혼란이 사라진다.

**Kebab 어포던스** (`MoreVertical` 아이콘, `md:hidden`): list view 각 행의 5번째 열로 추가, 우측 정렬, 32 px 탭 타깃. Grid view는 본 릴리스 범위 밖이라 kebab 미적용 — 거기서는 long-press만 항목 단위 제스처. kebab의 `onclick`은 우클릭 / long-press 경로와 동일한 `onMenu` 핸들러를 호출 — 세 경로 모두 동일한 메뉴 상태로 수렴. kebab click의 `stopPropagation`이 row의 `onSelect` 발화를 차단; kebab의 `onpointerdown` 핸들러는 row의 `longPress` action이 500 ms 타이머를 시작하는 것도 차단한다 — 그렇지 않으면 kebab을 누르는 동안 long-press 타이머가 bubbled pointerdown으로 fire되고, 이후 pointerup → click → kebab 핸들러가 다시 fire하여 메뉴가 두 번 열림.

**Inspector swipe-to-dismiss** (`Inspector.svelte`): 이미 렌더링되어 있던 (시각적이기만 했던) bottom-sheet 핸들에 표준 PointerEvent capture 패턴으로 `startDrag` / `moveDrag` / `endDrag` 포인터 핸들러 부착. 드래그 중에는 sheet의 `transform: translateY({dragOffsetY}px)`가 커서를 따라가며, 음수 값은 0으로 클램프 (sheet가 화면 바닥에 anchor 되어 있어 위로 끄는 것은 no-op). 릴리스 시: `dragOffsetY > 100`이면 `onClose()`, 아니면 `dragOffsetY = 0`으로 두어 기존 `transition-transform duration-150` 클래스가 snap-back을 애니메이션. 핸들은 `aria-hidden="true"` — 순수 시각적 — 이며 항상 노출되는 X 닫기 버튼(`aria-label="Close file details"`)이 스크린리더 접근 가능한 dismiss 경로로 남는다.

**데스크탑 시맨틱 변경 없음** (`viewportWidth >= 768`): single-click은 열지 않고 선택만, double-click이 열기 (기존 `dragEntry` action 경유), 우클릭은 "Select" 항목을 제외한 동일한 context menu 표시, Inspector는 우측에 360px side panel로 렌더링 (swipe 핸들러 없음).

## 2. Verification Summary

**정적 검사**
- `svelte-check`: 수정된 Explorer 영역에 0 errors / 0 warnings.
- `vite build`: 신규 에셋 와이어링과 함께 production 번들 성공.

**코드 리뷰** — 14-criteria 체크리스트에 대해 3-pass (correctness/UX, accessibility/event propagation, cross-component consistency). 적용된 auto-fix:
- Inspector 핸들러 이름을 12-char naming rule을 충족하도록 `startDrag` / `moveDrag` / `endDrag` 와 `dragPointer`로 정규화.
- kebab의 `stopRowLongPress` pointerdown 핸들러 추가 — row-level `longPress` action이 kebab의 click과 동시에 fire하여 메뉴가 두 번 열리는 것 방지.
- Inspector 핸들 ARIA를 `role="separator" aria-label="..."`(시맨틱 부정확 — separator는 그룹 간 divider 의미)에서 `aria-hidden="true"`로 변경 — 접근 가능한 dismiss는 X 닫기 버튼에 위임.

## 3. Known Limitations and Follow-ups

- **List view row가 키보드 포커스 대상이 아님**. kebab 버튼은 Tab으로 접근 가능 (실제 `<button>`)이지만 row 자체에는 `tabindex`나 `onkeydown` 항목 활성화 핸들러가 없음. Grid view는 이미 Enter로 열기를 지원. List row를 grid 수준으로 끌어올리는 것은 후속 개선으로 트래킹.
- **드래그 핸들은 키보드 dismiss를 지원하지 않음**. 의도적 — 모바일 전용 viewport에서만 노출되는 `md:hidden` 요소. 스크린리더 사용자는 `aria-label="Close file details"`를 가진 X 버튼으로 dismiss. swipe 제스처의 키보드 등가물은 계획에 없음.
- **`Explorer.svelte`가 767줄** — 사전 존재 조건, 코드 리뷰의 file-length 기준에서 플래그됨. 분리 작업 (marquee / selection / drag-drop / context-menu 와이어링을 별도 composable·action으로 추출)은 의미 있는 리팩토링이라 본 모바일 UX 변경을 묻지 않도록 별도 트래킹.
- **kebab은 list view 전용**. Grid view 타일은 context-menu 발견을 long-press에만 의존. grid 타일에 유사 어포던스(예: hover/active overlay 버튼) 추가는 본 릴리스 범위 밖 — 사용자 피드백이 요청하면 후속 작업으로.
