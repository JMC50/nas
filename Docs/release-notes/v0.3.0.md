v0.3.0 reorients the file Explorer for primary touch use without changing any desktop behavior. Single-tap on mobile now opens; long-press shows the same context menu desktop sees from right-click; a kebab affordance appears on every list-view row at viewports below the `md` breakpoint so the menu is reachable without learning the long-press gesture; and the Inspector — already rendered as a bottom sheet on mobile since v0.2.x — gains pull-down-to-dismiss on its drag handle.

---

## 1. Features

### 1.1 Mobile interaction model — single-tap open, long-press menu, kebab, swipe-to-dismiss

(commit `df3816a`)

**Behavior changes (mobile viewport, `viewportWidth < 768`):**

| Gesture | Old behavior | New behavior |
|---|---|---|
| Single-tap on entry (no selection) | Set single selection (highlight ring only) | **Open** — folder enters, file routes to the viewer registry |
| Single-tap on entry (active selection) | Toggle in/out of selection | Unchanged |
| Long-press on entry | Enter selection mode with that entry as anchor | **Open context menu** at touch point — same menu desktop sees from right-click |
| Tap kebab on list row | (kebab did not exist) | Open context menu anchored at the kebab |
| Pull Inspector handle | (handle was visual only) | Drag past 100px → close; shorter drag → snap back |

**Selection mode entry** (new path): the long-press menu has a "Select" item, mobile-only (`{#if ui.isMobile}` in `ContextMenu.svelte`). Tapping it seeds the selection with the long-pressed entry, after which the existing mobile selection bar appears and subsequent taps toggle membership. The dedicated mobile-only `onLongSelect` callback on `FileList` / `FileGrid` was removed — long-press is now uniformly "show menu" instead of mode-switching based on prior state, which removes the 500 ms delay that previously meant different things depending on whether a selection was active.

**Kebab affordance** (`MoreVertical` icon, `md:hidden`): added as a 5th column on every list-view row, right-aligned, 32 px tap target. Grid view does not get a kebab per scope (long-press is the only entry-level gesture there). The kebab's `onclick` calls the same `onMenu` handler the right-click and long-press paths use, so all three routes converge on identical menu state. `stopPropagation` on the kebab's click prevents the row's `onSelect` from firing; an `onpointerdown` handler on the kebab also stops the row's `longPress` action from starting its 500 ms timer (otherwise pressing the kebab would open the menu twice — once via the long-press timer firing at the bubbled pointerdown, then again via the pointerup → click → kebab handler).

**Inspector swipe-to-dismiss** (`Inspector.svelte`): the bottom-sheet drag handle (already rendered, was previously decorative) gets `startDrag` / `moveDrag` / `endDrag` pointer handlers using the standard PointerEvent capture pattern. While dragging, the sheet's `transform: translateY({dragOffsetY}px)` tracks the cursor, clamped to non-negative values (pulling up is a no-op since the sheet is bottom-anchored). On release: if `dragOffsetY > 100` → `onClose()`; otherwise `dragOffsetY = 0` and the existing `transition-transform duration-150` class animates the snap-back. The handle is `aria-hidden="true"` — purely visual — and the always-present X close button (`aria-label="Close file details"`) remains the screen-reader-accessible dismiss path.

**Desktop semantics unchanged** (`viewportWidth >= 768`): single-click selects without opening, double-click opens (via the existing `dragEntry` action), right-click shows the same context menu minus the "Select" item, Inspector renders as the 360px side panel pinned to the right with no swipe handlers.

## 2. Verification Summary

**Static checks**
- `svelte-check`: 0 errors, 0 warnings against the modified Explorer surface.
- `vite build`: production bundle succeeds with the new asset wiring.

**Code review** — three passes against the 14-criteria checklist (correctness/UX, accessibility/event propagation, cross-component consistency). Auto-fixes applied:
- Inspector handler names normalized to `startDrag` / `moveDrag` / `endDrag` and `dragPointer` to satisfy the 12-character naming rule.
- Kebab `stopRowLongPress` pointerdown handler added to prevent the row-level `longPress` action from firing alongside the kebab's click (would have opened the menu twice).
- Inspector drag handle ARIA changed from `role="separator" aria-label="..."` (semantically incorrect — separators denote dividers between groups) to `aria-hidden="true"`, deferring accessible dismissal to the X close button.

## 3. Known Limitations and Follow-ups

- **List-view rows are still not keyboard-focusable**. The kebab button is reachable via Tab (it's a real `<button>`), but the row itself has no `tabindex` and no `onkeydown` entry-activation handler. Grid view already supports Enter to open. Bringing list rows up to parity is tracked as a future improvement.
- **Drag handle does not support keyboard dismiss**. Pull-down is touch-only by design (mobile-only viewport, `md:hidden` element). Screen-reader users dismiss via the X button which has `aria-label="Close file details"`. No keyboard-equivalent gesture for swipe is planned.
- **`Explorer.svelte` is 767 lines** — pre-existing condition, flagged by the code-review file-length criterion. Splitting it out (extracting marquee, selection, drag-drop, and context-menu wiring into separate composables/actions) is a meaningful refactor and tracked separately so it doesn't bury the actual mobile UX changes here.
- **Kebab is list-view only**. Grid view tiles rely on long-press alone for context-menu discovery. Adding a similar affordance to grid tiles (e.g. an overlay button on hover/active) was out of scope; tracked as a follow-up if user feedback requests it.
