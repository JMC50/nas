v0.4.0 closes three endpoints that answered anonymous requests and replaces the interface with the dark "Signal" design.

---

## 1. Security: user list, permissions and activity log need a token

(commit `40fb7a2`)

Before v0.4.0, these routes answered without a token, also under the `/server` prefix:

| Route | Exposed |
|---|---|
| `/getAllUsers` | user IDs, names and permissions |
| `/getIntents?userId=...` | any user's permissions |
| `/getActivityLog` | all activity: user names, file names, paths |

Now:

| Route | Rule |
|---|---|
| `/getAllUsers` | signed-in user with the `ADMIN` intent |
| `/getIntents` | your own intents, or any user's for an admin |
| `/getActivityLog` | any signed-in user |

Anonymous requests get `401`, a non-admin asking for the user list or another user's intents gets `403`. The `/server/...` forms follow the same rules. The user manager, account and activity screens now send `Authorization: Bearer`, and a failed user-list request is shown on screen.

**Upgrade note:** a script that called these routes without a token must now send a token.

## 2. Signal interface

(commits `7ac9185`, `26e2c04`, `94a0080`, `11a68dd`, `2378789`, `319e8ce`)

- Dark only. The light theme and the theme toggle are removed.
- Fonts are bundled: Wanted Sans Variable for text, JetBrains Mono for code and paths (replacing Pretendard and FiraD2).
- Layout: a 64 px left icon rail from 1024 px up; below that a 48 px header with a menu drawer. A 40 px tab bar, a 28 px status bar, 36 px file rows with a 2 px selection bar.
- Text: body 14 px, secondary 12 px, headings 16 to 28 px. Body weight stays 550.
- Corners: 6 px controls, 8 px panels, 4 px chips.
- Notifications (toasts) now appear on screen; earlier versions queued them without showing them.
- The logo keeps its three-bar shape in lime. The favicon set and `Docs/images/logo.png` use the same mark.
- Every screen was restyled: explorer (toolbar, breadcrumbs, list and grid, menus, phone bottom sheet, details, empty folder), quick open, upload panel and drop overlay, settings, account, linked accounts, user manager, activity, system, music and video libraries, image, PDF and Office, video, audio and text viewers (Monaco Signal theme), sign-in and the Discord and Google callback screens.

All features, shortcuts (`Ctrl P`, `Ctrl W`, `Ctrl Tab`, `Ctrl S`), drag and drop, box selection and long-press menus are kept. The sidebar collapse button is gone because the rail replaces it. Below 640 px the list hides the modified column, below 768 px the type column; both stay in the details panel.

## 3. Accessibility and touch

(commits `e57674f`, `cdc2748`, `96933a1`, `32002b1`, `b171642`, `e4d76eb`)

- Reduced motion: shimmer and the equalizer stop; menus, quick open and the drawer use a 120 ms fade.
- Keyboard: file rows can be opened, selected and given a context menu from the keyboard; the tab close button shows on focus; focus rings are not clipped at scroll edges.
- Touch screens: tabs, tab close, breadcrumbs, status bar, segment buttons and rows are at least 44 px.
- Toolbar inputs and buttons share a 32 px height. Upload progress and the equalizer use the info color; lime is reserved for actions.
- Nested bordered boxes inside panels were removed. The Discord and Google callback error screens have a "Back to sign in" button. The background context menu stays inside the window.

Staging audit, v0.3.1 against v0.4.0:

| Check | v0.3.1 | v0.4.0 |
|---|---|---|
| Horizontal scroll | 1 of 148 captures | 0 of 149 |
| Text contrast below 4.5:1 | 93 pairs | 0 (lowest 4.75:1) |
| Keyboard focus failures | 74 of 232 stops | 0 of 234 (lowest ring contrast 7.39:1) |
| Touch targets under 44 px at 390 px | 695 | 48 |

The remaining 48 are segment buttons and switches whose tap area is widened to 44 px by padding; the measuring tool reads only their visible size.

## 4. Tests and staging

- 5 new integration tests in `backend/tests/integration/user_listing_test.go` cover anonymous, non-admin and admin access to the three routes.
- The integration test setup now uses the application's own `db.InitSchema` instead of a hand-written schema. This also fixes the two `TestLocalAuth_*` tests.
- Still failing exactly as on v0.3.1, unrelated to this release: `TestSafeJoin_NormalizesRedundantSeparators`, `TestAuthConfig_ReturnsStruct`, `TestReadFolderDetails`, `TestHealthz_ReturnsOK`, `TestTus_ResumeAfterInterruption`, `TestLegacyInput*` (2).
- `deploy/staging/` adds scripts that start a local staging NAS on `127.0.0.1` with seed data (commits `89f57da`, `e614fae`).

Not verified: Safari, Firefox, real phones, screen readers.

---

## 5. Upgrade notes

- No database schema change. Rolling back to `0.3.1` keeps the data valid.
- Clients that call `/getAllUsers`, `/getIntents` or `/getActivityLog` must send a bearer token.
- The light theme is gone. A stored light-theme preference is ignored.
