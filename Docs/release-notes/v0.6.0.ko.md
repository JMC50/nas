v0.6.0은 **여러 항목 zip 내려받기**를 더합니다. 로그인한 사용자가 파일과 폴더를 골라 zip 하나로 받습니다.

---

## 1. 여러 항목이나 폴더를 zip 하나로 내려받기

(커밋 `b8e4c94`, `4881d01`, `c4c4b20`)

**탐색기에서.** 항목을 여러 개 고르거나 폴더를 고른 뒤 Download를 누릅니다. 도구 막대의 새 Download 버튼, 오른쪽 클릭 메뉴의 Download, 터치 선택 막대의 내려받기에서 모두 됩니다. 드래그 선택, Ctrl과 Shift 선택, Ctrl+A는 전과 같습니다. 파일 하나만 골랐을 때는 전처럼 바로 받고, zip을 준비하는 동안에도 바로 받습니다.

**요청 두 번.** `POST /zip-downloads`가 고른 항목을 JSON 본문으로 보내고 수명이 짧은 주소를 받습니다. `GET /zip-downloads/{id}`가 zip을 흘려보내므로 브라우저의 일반 다운로드 진행 표시가 그대로 보입니다. 두 요청 모두 유효한 토큰과 `DOWNLOAD` 권한이 필요합니다. 서버는 임시 파일을 만들지 않습니다.

**규칙:**

- 주소는 2분 동안, 만든 사용자에게만 유효합니다. 다른 사용자는 `404`를 받습니다.
- 항목 이름은 고른 항목에서 시작합니다. 폴더 구조와 빈 폴더를 그대로 둡니다. 이름은 UTF-8로 저장합니다.
- 고른 항목 둘의 이름이 같으면 뒤의 것에 `report (2).txt` 같은 꼬리를 붙입니다.
- 파일 이름은 항목이 하나면 `<항목>.zip`, 한 폴더의 여러 항목이면 `<폴더>.zip`, 그 밖에는 `nas-download.zip`입니다.
- 파일은 공개 다운로드 링크와 같은 Go `os.Root`로 엽니다. 심볼릭 링크로 데이터 폴더 밖에 닿을 수 없습니다.
- 클라이언트가 연결을 끊거나, 30초 동안 읽지 않거나, 사용자가 `DOWNLOAD` 권한을 잃으면 전송을 멈춥니다.

**한도:**

| 한도 | 값 | 넘쳤을 때 응답 |
|---|---|---|
| zip 하나의 파일과 폴더 수 | `ZIP_DOWNLOAD_MAX_FILES`, 기본 20000 | `413`, `too_many_entries` |
| 압축 전 전체 크기 | `ZIP_DOWNLOAD_MAX_SIZE`, 기본 50gb | `413`, `too_large` |
| 사용자 한 명의 동시 zip 내려받기 | 2 | `429`, `Retry-After: 30` |
| 서버 전체의 동시 zip 내려받기 | 3 | `503`, `Retry-After: 30` |
| 요청 본문 | 1 MiB | `400` |

값을 `0`으로 두면 그 한도가 없어집니다. 두 변수는 넣지 않아도 됩니다.

**활동 기록.** zip 내려받기는 사용자 이름으로 `DOWNLOAD [ZIP]`을 남깁니다.

---

## 2. 올릴 때 알아 둘 것

- 데이터베이스 변경이 없고, 꼭 바꿔야 하는 설정도 없습니다.
- 새 환경 변수 `ZIP_DOWNLOAD_MAX_FILES`와 `ZIP_DOWNLOAD_MAX_SIZE`는 선택 사항입니다. `ZIP_DOWNLOAD_MAX_SIZE` 값이 잘못되면 서버가 시작할 때 설정 오류로 멈춥니다.
- 리버스 프록시는 `/zip-downloads`(와 `/server/zip-downloads`)를 다른 API 경로처럼 넘겨야 합니다.

---

## 3. 알려진 한계

- zip 전송에는 `Content-Length`가 없고 이어받을 수 없습니다. 받는 중에 서버를 다시 시작하면 그 내려받기는 끊깁니다.
- 서버는 준비한 주소를 모든 사용자를 합쳐 한 번에 256개까지만 둡니다. 한 사용자가 2분 안에 그만큼 준비하면, 주소가 만료될 때까지 다른 사용자는 `503`을 받습니다. 이미 받는 중인 zip은 영향이 없습니다.
- 읽지 못한 파일은 알림 없이 zip에서 빠집니다. 공개 다운로드 링크도 같은 규칙입니다.
- 압축 풀기는 `unzip`과 Python `zipfile`로 확인했습니다. Windows 탐색기, macOS 압축 유틸리티, 휴대폰 브라우저는 이번 릴리스에서 확인하지 않았습니다.
