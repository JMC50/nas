v0.6.0 adds **zip download of several items**: a signed-in user selects files and folders and downloads them as one zip.

---

## 1. Download several items or a folder as one zip

(commits `b8e4c94`, `4881d01`, `c4c4b20`)

**In the Explorer.** Select several items, or a folder, and choose Download. The action is the new Download button in the toolbar, the Download item in the right-click menu, and the download action of the touch selection bar. Drag selection, Ctrl and Shift selection, and Ctrl+A work as before. One selected file still downloads directly, also while a zip is being prepared.

**Two requests.** `POST /zip-downloads` sends the selection in a JSON body and returns a short-lived address. `GET /zip-downloads/{id}` streams the zip, so the browser shows its normal download progress. Both requests need a valid token and the `DOWNLOAD` intent. The server writes no temporary file.

**Rules:**

- The address is valid for 2 minutes and only for the user who made it. Another user gets `404`.
- Entry names start at the selected item. Folder structure and empty folders are kept. Names are stored as UTF-8.
- If two selected items have the same name, the later one gets a suffix such as `report (2).txt`.
- The file name is `<item>.zip` for one item, `<folder>.zip` for several items from one folder, and `nas-download.zip` otherwise.
- Files are opened through the same Go `os.Root` as public download links, so a symbolic link cannot lead outside the data folder.
- The stream stops when the client disconnects, when the client reads nothing for 30 seconds, or when the user loses the `DOWNLOAD` intent.

**Limits:**

| Limit | Value | Response when exceeded |
|---|---|---|
| Files and folders in one zip | `ZIP_DOWNLOAD_MAX_FILES`, default 20000 | `413`, `too_many_entries` |
| Total size before compression | `ZIP_DOWNLOAD_MAX_SIZE`, default 50gb | `413`, `too_large` |
| Zip downloads of one user at the same time | 2 | `429`, `Retry-After: 30` |
| Zip downloads of the server at the same time | 3 | `503`, `Retry-After: 30` |
| Request body | 1 MiB | `400` |

A value of `0` removes a limit. Both variables are optional.

**Activity log.** A zip download writes `DOWNLOAD [ZIP]` with the user name.

## 2. Upgrade notes

- No database change and no required configuration change.
- New optional environment variables: `ZIP_DOWNLOAD_MAX_FILES` and `ZIP_DOWNLOAD_MAX_SIZE`. An invalid `ZIP_DOWNLOAD_MAX_SIZE` value stops the server at startup with a configuration error.
- A reverse proxy must pass `/zip-downloads` (and `/server/zip-downloads`) like the other API routes.

---

## 3. Known limits

- A zip stream has no `Content-Length` and cannot be resumed. A restart of the server during a download ends that download.
- The server keeps at most 256 prepared addresses at one time, for all users together. When one user prepares that many within 2 minutes, other users get `503` until the addresses expire. Zip downloads that already run are not affected.
- A file that cannot be read is left out of the zip without a message. Public download links follow the same rule.
- Extraction was checked with `unzip` and Python `zipfile`. Windows Explorer, macOS Archive Utility, and phone browsers were not checked for this release.
