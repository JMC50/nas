# Release Notes v0.7.0 (한국어)

> [English version](https://github.com/JMC50/nas/blob/main/Docs/release-notes/v0.7.0.md)

> 초안입니다. 릴리스 단계에서 커밋 수를 고치고, 실제 발급자로 로그인한 확인 결과를 더합니다.

| | |
|---|---|
| 범위 | `v0.6.0..v0.7.0` |
| 커밋 | 릴리스 커밋 전까지 20개(기능 5, 보안 5, 버그 수정 3, 문서와 기타 7) |
| 구성 요소 | `backend/internal/auth`(OIDC 로그인, back-channel logout, 토큰 확인), `internal/config`, `internal/db`(새 열 하나), `internal/server` 경로, `cmd/server`(`oidc-link` 명령), 프런트엔드의 로그인 화면, 로그아웃, 관리자 권한 요청 버튼, `Docs/configuration/oidc-sso.md`, `Docs/development/api-reference.md` |
| 검증 | Go 전체 시험은 186개가 통과하고(하위 시험을 넣으면 248개) 실패 6개는 v0.6.0과 같은 이름입니다. `go vet` 통과, `go mod tidy -diff`는 차이가 없고, gofmt 목록은 v0.6.0과 같습니다. 전체 시험을 `go test -race`로 돌리면 data race 보고가 없고, 실패는 같은 6개와 이어 올리기 시험 2개입니다. 이어 올리기 시험은 v0.6.0에서도 일부 실행에서 실패합니다(이전 측정: 전에는 20번 가운데 6번, 뒤에는 40번 가운데 10번). `npm run check`는 예전부터 있던 `vite.config.ts` 오류 4개만 내고 `npm run build`는 성공합니다. OIDC 시험은 시험 안에서 도는 발급자를 씁니다. 이 발급자는 discovery, JWKS, 토큰 주소를 HTTP로 내줍니다. 이미지를 세 가지로 띄워 본 확인(`oidc` 모드의 닫힌 경로 `403`, 필수 값이 빠졌을 때 종료 코드 1, 기본 모드 로그인 화면이 v0.6.0과 픽셀이 같음)은 보안 수정 전 코드로 한 것이며 릴리스 단계에서 다시 합니다 |

v0.7.0은 **OpenID Connect 통합 로그인**을 더합니다. `AUTH_TYPE=oidc`로 두면 발급자 하나로만 로그인합니다. `local`, `oauth`, `both`를 그대로 쓰는 배포는 전과 같이 동작하고 새 설정이 필요 없습니다.

---

## 1. 통합 로그인 모드(`AUTH_TYPE=oidc`)

(커밋 `ea98df0`, `e72f5e8`, `74e7a98`, `02d8212`, `3d49e4e`, `c5ec7c3`, `ea067a3`)

**하는 일.** 로그인 화면에 아이디와 비밀번호 입력란이 없고 Discord와 Google 버튼도 없습니다. 화면은 브라우저를 발급자로 보냅니다. 발급자에서 로그인하면 NAS에도 로그인됩니다.

**흐름.** PKCE(`S256`), `state`, `nonce`를 쓰는 인가 코드 흐름입니다. NAS는 discovery 문서에서 주소와 키를 읽고 ID 토큰의 서명, 발급자, 대상, 만료, nonce를 확인합니다. 돌아올 주소는 `OIDC_REDIRECT_URI`에서만 옵니다. state 쿠키와 토큰을 넘기는 쿠키는 `Secure`, `HttpOnly`, `SameSite=Lax`이고 수명이 짧습니다(10분, 60초). state 쿠키는 이름 끝에 state가 붙어서 로그인 시도마다 따로 있습니다. 그래서 두 탭에서 동시에 로그인해도 한쪽이 실패하지 않습니다. 끝내지 않은 로그인이 5개 쌓이면 다음 로그인이 그 쿠키들을 지웁니다. NAS 토큰은 주소에 실리지 않습니다.

**설정:**

| 변수 | 필수 | 기본값 |
|---|---|---|
| `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `OIDC_REDIRECT_URI` | `AUTH_TYPE=oidc`일 때 필수 | |
| `OIDC_IDP_HINT` | 선택 | |
| `OIDC_SCOPES` | 선택 | `openid profile email groups` |
| `OIDC_GROUPS_CLAIM` | 선택 | `groups` |
| `OIDC_MEMBER_GROUP`, `OIDC_ADMIN_GROUP` | 선택 | `nas_member`, `nas_admin` |
| `OIDC_LOGOUT_URL` | 선택 | 발급자의 `end_session_endpoint` |

`AUTH_TYPE=oidc`인데 필수 값이 빠지면 서버가 시작하지 않고 빠진 변수 이름을 알립니다. `OIDC_ISSUER`는 `https`여야 합니다. 평문 `http`는 `localhost`와 `127.0.0.1` 같은 loopback 주소에서만 받습니다.

**`AUTH_TYPE` 값 검사.** `docker run --env-file`은 따옴표, 줄 끝 공백, 값 뒤의 `# 주석`을 값에 그대로 넣습니다. 그래서 서버는 다음 두 경우에 시작하지 않습니다.

- 공백, 따옴표, 주석을 지우고 소문자로 바꾸면 `oidc`인데 원래 값이 정확히 `oidc`가 아닌 경우. 예: `OIDC`, `oidc   # 주석`
- `AUTH_TYPE`이 `local`, `oauth`, `both`, `oidc`가 아닌데 `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `OIDC_REDIRECT_URI` 가운데 하나라도 있는 경우

그 밖의 모르는 값은 v0.6.0처럼 시작하고 로그에 `AUTH_TYPE is not one of local, oauth, both, oidc` 경고를 남깁니다.

**사용자와 그룹:**

- NAS는 `sub` 클레임으로 사용자를 찾습니다(신원 `oidc`). 없으면 사용자를 만듭니다.
- 구성원 그룹은 새 사용자에게 `VIEW`, `OPEN`, `DOWNLOAD`, `UPLOAD`, `COPY`, `RENAME`을 줍니다. 관리자 그룹은 `ADMIN`을 줍니다.
- 두 그룹 어디에도 없는 사람은 거부되고 사용자가 만들어지지 않습니다.
- 그룹은 사용자를 만들 때만 권한을 정합니다. 그 뒤의 변경은 사용자 관리 화면에서 합니다.

**닫힌 경로.** 이 모드에서 서버는 로컬 로그인과 가입, 비밀번호 변경, Discord와 Google의 콜백과 가입, 계정 연결 경로, 신원 삭제, 관리자 비밀번호로 `ADMIN`을 얻는 `POST /requestAdminIntent`에 `403`으로 답합니다. 비밀번호로 얻는 권한은 없습니다. `ADMIN`은 관리자 그룹이나 관리자의 사용자 관리 화면으로만 받습니다. 프런트엔드는 이 모드에서 관리자 비밀번호를 묻는 버튼을 보이지 않습니다. `GET /auth/config`는 OIDC만 알립니다.

**로그아웃.** 프런트엔드가 NAS 토큰을 지우고 발급자의 세션 종료 주소를 엽니다.

설정 안내: [Single Sign-On with OpenID Connect](https://github.com/JMC50/nas/blob/main/Docs/configuration/oidc-sso.md).

## 2. back-channel logout과 토큰 유효 시각

(커밋 `5307d52`, `e72f5e8`, `40686bb`, `be896ab`, `8a07c96`)

**back-channel logout.** 발급자가 `logout_token`을 실어 `POST /auth/oidc/backchannel`을 부를 수 있습니다. NAS는 서명, `iss`, `aud`, `exp`, `iat`, logout 이벤트, `nonce`가 없는지를 확인합니다. 이미 쓴 토큰은 받지 않습니다. 요청 본문은 8 KiB까지 받습니다. 4096비트 RSA 키로 서명한 `logout_token`이 1.3 KiB쯤입니다.

**응답 코드.** 토큰이 잘못되었으면 `400`입니다. NAS가 발급자의 discovery 문서나 키를 읽지 못해서 토큰을 확인하지 못했으면 `503`입니다. 발급자는 같은 토큰을 다시 보낼 수 있습니다.

**토큰 유효 시각.** 사용자마다 새 값 `tokens_valid_after`가 있습니다. 기본은 비어 있고, 비어 있으면 제한이 없습니다. back-channel logout이 이 값을 지금 시각으로 바꿉니다. 그러면 토큰 확인이 그 사용자의 토큰 가운데 그보다 먼저 발급된 것을 `401`로 거부합니다. 새 토큰에는 이 비교에 쓰는 `issued_at` 클레임이 들어갑니다.

`oidc` 모드에서는 NAS에서 지워진 사용자의 토큰도 거부합니다. 첫 로그인에서 사용자를 만들 때 `tokens_valid_after`를 만든 시각으로 둡니다. 그래서 지워진 사용자가 다시 로그인해 같은 `userId`로 새 사용자가 생겨도 지워진 사용자의 토큰은 계속 거부됩니다. 방금 만든 사용자에게 바로 내준 토큰은 같은 밀리초여도 통과합니다.

## 3. 기존 배포를 위한 `oidc-link` 명령

(커밋 `7d4bace`, `d413279`)

`oauth`나 `local`에서 `oidc`로 옮기는 배포는 이 명령으로 사용자를 그대로 둡니다. 명령은 사람마다 예전 ID와 새 `sub`를 적은 CSV 파일을 읽고, 기존 사용자에게 `oidc` 신원을 더합니다. 사용자 ID, 권한, 파일은 그대로입니다.

```bash
docker exec nas-app /app/server oidc-link --map /tmp/oidc-map.csv --from google --dry-run
```

- `--dry-run`은 줄마다 결과를 알리고 아무것도 쓰지 않습니다.
- 같은 파일로 다시 실행해도 됩니다.
- 파일 맨 앞의 UTF-8 BOM(엑셀이 붙임)과 값 앞뒤의 공백은 무시합니다.
- 출력에는 NAS 사용자 이름과 줄 번호가 나옵니다. ID, `sub`, 비밀 값은 나오지 않습니다.

## 4. 올릴 때 알아 둘 것

- **다른 모드는 그대로입니다.** `AUTH_TYPE`을 넣지 않았거나 `local`, `oauth`, `both`이면 새 설정이 필요 없고 `OIDC_*` 변수를 읽지 않습니다. 관리자 비밀번호 경로도 전과 같습니다. `GET /auth/config` 응답의 필드는 v0.6.0과 같습니다.
- **다른 모드의 `/auth/oidc/` 주소.** 이 주소에는 경로가 없어서 모르는 주소와 같이 처리됩니다. Docker 이미지처럼 `FRONTEND_DIR`이 있으면 `POST`까지 `200`과 프런트엔드의 `index.html`로 답하고, 없으면 `404`입니다. 어느 쪽이든 쿠키를 두지 않고 NAS에서 바뀌는 것이 없습니다. `oidc`에서 다른 모드로 되돌린 배포는 발급자의 back-channel logout 주소를 지우십시오.
- **`AUTH_TYPE` 값.** 위의 두 경우에 해당하는 값은 이제 시작을 막습니다. 그 밖의 모르는 값은 전과 같이 시작하고 경고만 남깁니다.
- **데이터베이스.** 서버가 시작할 때 `users.tokens_valid_after` 열을 더합니다. 자동이고 모든 행을 그대로 둡니다. 바뀐 데이터베이스로 v0.6.0도 시작합니다.
- **토큰.** v0.6.0이 내준 토큰은 계속 유효합니다. 올린다고 로그아웃되는 사람은 없습니다.
- **토큰 확인.** 토큰이 실린 요청마다 사용자의 `tokens_valid_after`를 읽습니다. `POST /log`, 이어 올리기 시작, 비밀번호 변경도 같은 확인을 씁니다.
- **다른 모드의 프런트엔드.** 로그인 화면의 안내 문구는 설정을 읽은 뒤에 나옵니다. 로그아웃은 화면을 떠나기 전에 `/auth/config`를 읽습니다.
- **리버스 프록시.** `oidc`를 쓰는 배포는 `/auth/oidc/`를 다른 API 경로처럼 넘겨야 하고, NAS를 HTTPS로 내보내야 합니다.
- **새 의존성.** `github.com/coreos/go-oidc/v3` v3.21.0과 `golang.org/x/oauth2` v0.36.0, 그리고 이 둘이 쓰는 `github.com/go-jose/go-jose/v4` v4.1.9. go-jose v4.1.4에는 공개 취약점이 있어서(GHSA-mgcc-cww5-fp2q, GHSA-4w3g-jfj2-cw2q, GHSA-vvm8-gf78-28g4) 고쳐진 v4.1.9를 씁니다. 인증 없이 부를 수 있는 `/auth/oidc/backchannel`이 이 라이브러리로 토큰을 읽습니다.

## 5. 알려진 한계

- 이미 쓴 `logout_token`의 ID 목록은 메모리에 있습니다. 서버를 다시 시작하면 5분이 안 된 `logout_token`을 한 번 더 받습니다.
- `sub` 없이 `sid`만 있는 `logout_token`은 받지 않습니다.
- `logout_token`의 서명 키를 모르면 NAS가 발급자의 키를 다시 읽습니다. `/auth/oidc/backchannel`이 공개 주소이면 리버스 프록시에서 요청 빈도를 제한하십시오.
- go-jose v4.1.6부터 4096비트보다 큰 RSA 키를 받지 않습니다. 발급자의 서명 키가 그보다 크면 로그인과 back-channel logout이 되지 않습니다.
- 사용자의 공개 다운로드 링크는 back-channel logout 뒤에도 유효합니다.
- 운영 환경(`NODE_ENV=production`)에서는 `oidc` 모드에서도 `ADMIN_PASSWORD`가 있어야 서버가 시작합니다. 이 모드는 그 값을 쓰지 않습니다.
- `NODE_ENV`가 `production`이 아니면 `PRIVATE_KEY` 없이도 서버가 시작하고, 빈 키로 서명한 토큰을 받습니다. v0.6.0부터 그렇습니다. Docker 이미지와 `docker-compose.yml`은 `NODE_ENV=production`을 둡니다. 실제 배포에서는 이 값을 바꾸지 마십시오.
- Discord와 Google 로그인 코드는 서버에 남아 있고, 모드로만 닫습니다.
